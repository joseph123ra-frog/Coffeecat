# 깝휘캣 피드백 반영

사용자가 특정 게시물에 대한 피드백을 날것 그대로 준다. 이걸 **앞으로의 모든 게시물에 적용되는 규칙**으로 바꿔 반영하고, 무엇을 바꿨는지 알려 준다.
모델을 다시 학습시키는 게 아니라, 매번 Claude에게 함께 전달되는 편집 지침을 다듬는 것이다.

## 관련 파일
| 파일 | 역할 | 피드백 종류 |
|---|---|---|
| `prompts/guidelines.md` | 편집 지침. 조사·원고 두 단계에 그대로 전달된다 | **대부분 여기** (질문 이해, 조사, 구성, 말투, 사진 검색어) |
| `src/research.js` | 시스템 지시문, `REQUEST_RULES`, 원고 스키마(글자 수 제한 등) | 지침으로 안 되는 구조적 문제만 |
| `templates/slide.js`, `templates/styles.js` | 슬라이드 디자인 | 디자인·레이아웃 피드백 |
| `src/config.js` | 장수, 예산, 게시 횟수 등 | 운영 설정 |
| `archive/noXXX-날짜.json` | 게시물별 질문·원고(`draft`)·캡션·출처·URL | 피드백 대상 확인용 |
| `feedback/log.md` | 반영 기록 | 매번 추가 |

## 절차

1. **게시물 찾기**: `archive/`에서 사용자가 말한 게시물을 찾는다. 호수(No.3, 3호)나 제목·주제 키워드로 찾고, 애매하면 후보를 보여 주고 묻는다. 기록이 없으면(No.01은 기록 없음) 사용자 설명만으로 진행한다.

2. **대조와 진단**: 질문 칸 원문(`question`), 실제 원고(`draft`), 피드백을 나란히 놓고 원인이 어느 단계인지 고른다.
   - 질문 이해: 의도를 다르게 읽음, 요청 일부를 빠뜨림
   - 자료 조사: 출처 부족·편중, 원하는 자료를 못 찾음
   - 원고 구성: 흐름, 장별 배분, 결론
   - 표현·말투: 어투, 용어, 길이
   - 사진: 검색어가 내용과 안 맞음
   - 디자인: 레이아웃·글자 크기 등 (지침이 아니라 템플릿 문제)
   진단이 애매하면 추측하지 말고 사용자에게 한 번 묻는다.

3. **일반 규칙으로 바꾸기**: 그 게시물에만 맞는 수정("야구 글에서 KBO를 더")이 아니라, 같은 종류의 질문 전체에 통하는 규칙("국내외 자료가 모두 있는 주제는 한국 자료 비중을 해외와 비슷하게")으로 쓴다.
   - 칭찬받은 점도 유지할 가치가 있으면 규칙으로 남긴다.
   - 기존 규칙과 겹치면 합치고, 충돌하면 새 피드백 쪽으로 고치되 충돌했다는 사실을 사용자에게 알린다.
   - 규칙은 한 줄, 구체적으로. 지침 파일 전체가 60줄을 넘으면 비슷한 규칙을 묶어 줄인다.

4. **반영**:
   - 지침 문제 → `prompts/guidelines.md`의 해당 섹션에 추가·수정.
   - 디자인 문제 → 템플릿을 고치고 `node src/render.js samples/sample.json --style split --out out/samples`로 렌더링해 결과 이미지를 사용자에게 보여 준다.
   - 장수·예산·게시 횟수·원고 스키마를 바꾸는 일은 영향이 크니 **바꾸기 전에 사용자에게 확인**한다.
   - `feedback/log.md` 맨 위에 기록을 추가한다: 날짜 · 호수 주제 / 피드백(요약) / 진단 / 반영 내용(파일 › 섹션 › 규칙).

5. **적용되게 저장하기**: 자동 게시는 저장소 **기본 브랜치**의 파일로 돈다. 변경이 기본 브랜치에 들어가야 다음 게시물부터 적용된다.
   - 기본 브랜치 이름은 `git remote show origin`의 HEAD branch로 확인한다.
   - 지금 세션 브랜치가 기본 브랜치와 다르면, 사용자에게 "기본 브랜치에 바로 반영할까요?"라고 한 번 묻고 동의하면 기본 브랜치에 커밋·push한다.
   - 커밋 메시지: `피드백 반영: No.N 주제 - 바뀐 규칙 요약`

6. **보고**: 짧게.
   - 이해한 피드백 한 줄
   - 진단 (어느 단계 문제였는지)
   - 바뀐 내용: 변경 전 → 변경 후 (지침 문장 그대로)
   - 언제부터 적용되는지 (다음 정기 게시부터)

## 하지 않는 것
- 이미 올라간 게시물을 수정·재게시하지 않는다. 필요하면 따로 묻는다 (재게시는 `.github/workflows/repost.yml`, 원본 슬라이드는 실행 후 하루만 남음).
- 피드백 한 건으로 지침을 통째로 다시 쓰지 않는다. 필요한 부분만 고친다.
- 근거 없이 "다른 것도 개선했다"며 피드백에 없는 규칙을 추가하지 않는다. 제안은 보고에 따로 적고 사용자가 고르게 한다.
